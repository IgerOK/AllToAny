# .project-memory — памятка для пользователя

Папка — «память» проекта для любого AI-агента. Агент читает её перед
работой и обновляет в ходе сессии. Никаких API и сервисов: только файлы
и git. Система одинаковая для любого агента — облачного или локального.

## Откуда

- Создана в этом репозитории 2026-11-08 как универсальная система памяти
  проекта (заменила Freebuff-специфичную память).
- В другом проекте используется одним из двух способов:
  1. Скопировать папку `.project-memory/` в корень проекта — и всё:
     всякое необходимое (протокол, журнал, скрипты, git-хук) внутри папки.
  2. Ссылаться на опубликованный GitHub-репозиторий — агенту достаточно
     ссылки на репозиторий или на `AGENTS.md`.
- Полная инструкция: `README.md` в корне проекта.

## Что внутри

| Файл | Зачем | Обновляет |
| --- | --- | --- |
| `AGENTS.md` | Протокол: что агент делает до, во время и после сессии. Содержание не менять. | — |
| `CONTEXT.md` | Состояние проекта: цель, стек, как запускать, следующие шаги. | Агент в конце сессии |
| `TASK.md` | Активная задача: статус, «текущее состояние», следующий шаг. | Агент по событиям |
| `QUESTIONS.md` | Нерешённые вопросы, ожидающие решения пользователя. | Агент + пользователь |
| `SESSIONS.md` | Журнал сессий, append-only (последние 8 записей, старые — в `archive/`). | Агент после каждой сессии |
| `DECISIONS.md` | Принятые решения и почему; история не стирается. | Агент при решениях |
| `.in-progress.md` | Черновик краш-безопасности: заметки пишутся во время сессии, чтобы при сбое процесс не терял работу. | Агент во время сессии |
| `memory-check.sh` | Проверка здоровья памяти: «зависший» черновик, разросшийся журнал, утечка секретов. | — |
| `memory-autosave.sh` | Спасательный коммит несохранённой памяти. | Агент / пользователь, в любой момент |
| `pre-commit` | Опциональный git-хук: подмешивает память в каждый коммит, запускает `memory-check.sh`. | Агент / пользователь (opt-in) |
| `archive/INDEX.md` | Индекс старых записей журнала, уехавших в `archive/YYYY-MM.md`. | Агент при ротации |

## Что делает пользователь (три шага)

1. Перед работой сказать агенту: «Работай по протоколу в
   `.project-memory/AGENTS.md`» — агент сам прочитает контекст и
   продолжит с того места, где остановилась прошлая сессия.
2. Во время сессии ручных действий не нужно — файлы обновляет агент.
3. Периодически смотреть `SESSIONS.md` и `DECISIONS.md`, чтобы видеть
   результат и принятые решения.

## Защита от краха (опционально)

- `bash .project-memory/memory-autosave.sh` — спасательный коммит несохранённой памяти.
- `git config core.hooksPath .project-memory` — разовая настройка: память
  подмешивается в каждый коммит, `memory-check.sh` запускается при коммите
  (если хук на Windows не выполняется — `chmod +x .project-memory/pre-commit`).
